# Insider Scanner PR grouping

Based on [the codebase review](CODEBASE_REVIEW_2026-11-14.md), with the same scope: European scraping remains excluded. This proposal assigns all **240 canonical appendix findings** to **26 PRs plus one conditional PR**. Refuted findings are excluded; aliases stay with their canonical finding.

The landing order puts test safety and shared contracts first, then persistence and ingestion, then their consumers. The prerequisites below identify dependencies without requiring every PR to run in sequence: independent branches can proceed once their prerequisites land. Each behavior change includes its focused regression tests. Changes to stored data, keys or paths must preserve existing user state and include the necessary migration or repair.

## Decisions that affect the grouping

- **Replace checkpoint machinery once.** PR 13 follows explicit outcomes and atomic batch persistence. Avoid a series of interim JSON-checkpoint fixes that the ledger immediately replaces. The archive cursor in PR 14 must retain retryable failures behind it.
- **Establish data meaning before importing another format.** Normalization, owner/derivative semantics and raw transaction identity precede amendments and datasets. PR 16 preserves the SEC/scraper source rows used for comparison while fixing effective user-facing transactions. Cross-source deduplication must not erase that evidence.
- **Keep the dataset path independent of exhaustive legacy tuning.** PR 18 does not depend on PR 14's archive/cache optimizations, PR 17's feed scalability work or PR 27's concurrency. The review gives the dataset boundary as 2006 Q1; the 2003–2005 interval and unpublished quarter need explicit treatment. A wholesale GUI or application rewrite is also not a prerequisite.
- **Use the verifier's narrower claims.** Successful duplicate bulk accessions already skip fetching; coverage freshness concerns recent filing/publication dates, not an assumed universal 45-day disclosure lag. Keep documented nonfatal per-filing CLI semantics unless deliberately changed. Retain the concurrency regression protection in TESTS-07 and the XML security limits. Evaluate index removals against ledger and amendment access patterns.
- **Preserve three summary concerns despite conflicting aliases.** OpenInsider's result cap (`USSVC-03` / `ARCH-02`) and Senate's result cap (`CONGRESS-05`) belong to PR 06. Current-day price-bar freshness (`CONGRESS-M1`) belongs to PR 19. Their appendix aliases instead point to swallowed errors, amendments and interior price gaps respectively; confirm these separate summary concerns during those PRs rather than silently treating them as covered by an alias. The qualified Senate end-date/session findings also require confirmation before changing behavior.
